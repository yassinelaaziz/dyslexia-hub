Dyslexia Grand Hub - API Specification

Version: 1.0 Date: 2026-10-31 Author: Senior Tech Lead (Devin) Status: Data Design Phase - Complete

API Style Choice

Choice: REST API Justification:
  • Simplicity: Easier to understand and implement than GraphQL
  • Caching: Better HTTP caching support (browser, CDN)
  • Offline-First: Simpler to implement local API layer
  • Tooling: Mature ecosystem (Postman, Swagger/OpenAPI)
  • Mobile: Easier to work with React Native networking
Future Consideration: GraphQL could be added for complex queries if needed

Base URL

Local Development: http://localhost:3000/api Staging: https://staging.dyslexia-hub.com/api Production: https://api.dyslexia-hub.com (if backend is deployed) Note: MVP is client-side only (no backend API needed). This specification is for optional cloud sync and future backend features.

Authentication Strategy

Option 1: No Authentication (MVP)

Strategy: Client-side only, no backend
  • All data stored locally
  • No authentication needed
  • Cloud sync not available

Option 2: JWT Authentication (Future)

Strategy: If cloud sync is enabled Login Endpoint: POST /api/auth/login Request Body: 
{

"email": "user@example.com",


"password": "password"


}
Response (200 OK): 
{

"token": "jwt-token",


"userId": "uuid-v4",


"expiresAt": "2026-11-30T00:00:00Z"


}
Token Format:
  • Header: Authorization: Bearer
  • Claims: userId, email, exp, iat
  • Expiration: 30 days

Option 3: OAuth 2.0 (Future)

Strategy: Social login (Google, GitHub) Authorization Flow:
  1. Redirect to OAuth provider
  2. User authorizes
  3. Provider redirects to callback URL with code
  4. Exchange code for access token
  5. Create or update user account
  6. Return JWT token

Error Handling Strategy

HTTP Status Codes

  • 200 OK - Success
  • 201 Created - Resource created
  • 204 No Content - Success, no response body
  • 400 Bad Request - Invalid input
  • 401 Unauthorized - Authentication required
  • 403 Forbidden - Insufficient permissions
  • 404 Not Found - Resource not found
  • 409 Conflict - Resource conflict
  • 422 Unprocessable Entity - Semantic error
  • 429 Too Many Requests - Rate limit exceeded
  • 500 Internal Server Error - Server error
  • 503 Service Unavailable - Service temporarily unavailable

Offline-First Considerations

Local API Layer

Design: Mirror cloud API with local implementation Example: 
class LocalAPIClient {

async createScreeningResult(data: ScreeningResult): Promise {


// Save to IndexedDB


const db = await openDB();


await db.add('screeningResults', data);


return data;


}



async getScreeningResults(userId: string): Promise {


// Read from IndexedDB


const db = await openDB();


return db.getAllFromIndex('screeningResults', 'userId', userId);


}


}

Sync API Layer

Design: Wrapper that decides local vs. cloud Example: 
class SyncAPIClient {

async createScreeningResult(data: ScreeningResult): Promise {


// Always save locally first


const localClient = new LocalAPIClient();


const result = await localClient.createScreeningResult(data);



// If online, sync to cloud


if (navigator.onLine && userPreferences.enableCloudSync) {


try {


await cloudClient.createScreeningResult(data);


} catch (error) {


// Queue for background sync


syncQueue.add('screeningResult', data);


}


}



return result;


}


}
