Dyslexia Grand Hub - Deployment Plan

Version: 1.0 Date: 2026-10-31 Author: Senior Tech Lead (Devin) Status: Deployment Phase - Complete

Hosting Strategy

Primary Choice: Vercel Justification:
  • Free tier sufficient for MVP
  • Automatic HTTPS
  • Global CDN
  • Preview deployments
  • Easy GitHub integration
Alternative: Netlify Justification:
  • Similar benefits to Vercel
  • Edge functions for future backend
Backend (Future): Railway or Render Justification:
  • Simple PostgreSQL hosting
  • Good free tier
  • Easy deployment

CI/CD Pipeline

Tool: GitHub Actions Workflow: 
name: CI/CD

on:


push:


branches: [main]


pull_request:


branches: [main]



jobs:


test:


runs-on: ubuntu-latest


steps:


- uses: actions/checkout@v3


- uses: actions/setup-node@v3


- run: npm install


- run: npm run test


- run: npm run lint


- run: npm run build



deploy-preview:


if: github.event_name == 'pull_request'


runs-on: ubuntu-latest


steps:


- uses: actions/checkout@v3


- uses: amondnet/vercel-action@v20


with:


vercel-token: ${{ secrets.VERCEL_TOKEN }}


vercel-org-id: ${{ secrets.VERCEL_ORG_ID }}


vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID }}


vercel-args: '--preview'



deploy-production:


if: github.event_name == 'push' && github.ref == 'refs/heads/main'


runs-on: ubuntu-latest


steps:


- uses: actions/checkout@v3


- uses: amondnet/vercel-action@v20


with:


vercel-token: ${{ secrets.VERCEL_TOKEN }}


vercel-org-id: ${{ secrets.VERCEL_ORG_ID }}


vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID }}


vercel-args: '--prod'

Build and Deployment Process

Build Process:
  1. npm install - Install dependencies
  2. npm run lint - Lint code
  3. npm run test - Run tests
  4. npm run build - Build for production
  5. Output: dist/ directory
Deployment Process:
  1. GitHub Actions triggers on push to main
  2. Tests run automatically
  3. If tests pass, deploy to Vercel
  4. Vercel builds and deploys globally
  5. Preview deployments for PRs
  6. Production deployments for main branch

Environment Configuration

Environments:
  • Development (local)
  • Preview (PR deployments)
  • Production (main branch)
Configuration: 
const config = {

environment: process.env.NODE_ENV || 'development',


apiBaseUrl: process.env.VITE_API_URL || '',


enableCloudSync: process.env.VITE_ENABLE_CLOUD_SYNC === 'true',


enableAnalytics: process.env.VITE_ENABLE_ANALYTICS === 'true',


analyticsId: process.env.VITE_ANALYTICS_ID,


};
Environment Variables:
  • VITE_API_URL - API base URL (future)
  • VITE_ENABLE_CLOUD_SYNC - Enable cloud sync (future)
  • VITE_ENABLE_ANALYTICS - Enable analytics
  • VITE_ANALYTICS_ID - Analytics ID

Database Migrations

Local Storage (IndexedDB):
  • Version tracking in sync metadata
  • Automatic migration on app startup
  • Backup before migration
  • Rollback on failure
Cloud Storage (PostgreSQL - Future):
  • Migration files in migrations/ directory
  • Run migrations on deployment
  • Use database migration tool (node-pg-migrate)
  • Rollback capability

Rollback Procedures

Vercel Rollback:
  1. Go to Vercel dashboard
  2. Select project
  3. Go to Deployments
  4. Click rollback to previous deployment
  5. Verify rollback
Alternative: Git revert and redeploy

Blue-Green Deployment Strategy

Future Implementation:
  • Two production environments (blue, green)
  • Deploy to green first
  • Run smoke tests
  • Switch traffic to green
  • Keep blue as rollback target

Conclusion

This deployment plan provides:

  • Hosting Strategy: Vercel for web, Railway for backend (future)
  • CI/CD Pipeline: GitHub Actions with automated testing
  • Build Process: Install → Lint → Test → Build
  • Environment Management: Dev, Preview, Production
  • Rollback Strategy: Vercel rollback or Git revert
  • Blue-Green Deployment: Future enhancement
